# フェーズ報告

**読者:** コーディングエージェント。`/phase-report` で呼び出される。
**役割:** 毎フェーズ同じ項目で報告し、本人が次のフェーズへ進むか判断できるようにする。

以下の項目をこの順で書く。未確認の項目は「未確認」と書き、埋めるために推測しない。

1. **実行方法:** 動かすコマンド。実際に確認した OS、コンパイラ、依存ライブラリの版。報告時点のブランチ名とコミットハッシュ。
2. **変更範囲:** 触れたファイル。フェーズ文書の実装範囲のうち、どこまで実装したか。
3. **観察結果:** スクリーンショットまたは動画。比較した設定と、それぞれで見えた動き。
4. **数値記録:** [docs/02_experiment_protocol.md](../../../docs/02_experiment_protocol.md) の指標。同条件の再実行で再現したか。
5. **問題:** 数値破綻(NaN/Inf)、消滅、静止、全面飽和、パフォーマンス。起きた条件を隠さず書く。
6. **C++ の学習ポイント:** 盤面の所有、現在/次の更新、境界処理、時間刻み、計算量。コードの該当箇所を示す。
7. **次段階の候補:** 本人に判断してほしい観察上の論点。数値パラメータは観察なしに固定しない。

報告は本人が読んで判断するためのもの。「うまくいった」と書く前に、どの指標でそう言えるかを示す。
