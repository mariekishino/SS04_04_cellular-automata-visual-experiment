# 03 — 段階的な開発ロードマップ

**読者:** 全員。
**役割:** Phase 0〜7 の全体像を示す。現在のフェーズは [README.md](../README.md) の「現在のフェーズ」が正本。各フェーズの詳細な実装指示は [phases/](phases/) に置き、直前の観測結果を受けて決める。

## 8 つのフェーズ

| Phase | 目的 | 次に進むための成果 |
| --- | --- | --- |
| **0 モデル探索** | Life から連続 CA・反応拡散へ進み、少なくとも 2 種の小さな可視化試作を比較する | 更新式・初期条件・境界条件、映像と指標、Phase 1 候補と選択理由 |
| **1 自律的な身体** | 選んだモデルで、無音でも動く単体アプリを作る | seed、固定刻み、停止・再開、リセット。継続した動きと局所的なまとまりの観察 |
| **2 音への即時応答** | 合成パルス、次に WAV を入力し、内部更新に作用させる | 同条件の無音／音ありで違いを確認。音停止後の短期応答の減衰 |
| **3 履歴** | 刺激の移動平均など、時定数の長い内部状態を 1 つ追加する | 現在の音が同じでも、履歴によって一時的な差が出るかを測る |
| **4 可塑性** | 感受性など 1〜2 個の係数を、経験に応じて更新する | 無音区間または共通刺激の後にも残る差と、変更された係数の記録 |
| **5 更新則の可変化(任意)** | 必要なら近傍の重みや成長関数を変化させる | 何を変えたかが追跡でき、数値的に破綻しない。Phase 4 で十分なら省略 |
| **6 個体差の比較** | 同じ初期状態を異なる入力履歴にさらし、後から同一刺激を与える | 再現可能な比較データ。違いが出なければ、その結果も保存 |
| **7 意味入力(任意)** | 必要なら言語や LLM から低頻度の環境入力を追加する | 切り離しても Phase 0〜6 が動き、意味入力の影響を比較できる |

## 補足

- **Phase 4 と 5 の違い:** Phase 4 の係数更新も数学的には更新則の一部です。Phase 5 は更新式の形や近傍重みそのものを変える、という実装上の区別です。
- **最初の制作目標は Phase 0〜2。** 長期的な問いは Phase 3〜4 です。長期目標があるからといって、初回のコードにそれらの機能を含めません。
- **フェーズを進める条件:** 本人が観察結果を確認してから、次のフェーズ文書を具体化します。手順は [04_development_workflow.md](04_development_workflow.md) を参照。
