# 01 — 構成と技術方針

**読者:** 実装者(本人とコーディングエージェント)。
**役割:** 技術の選択と、責務の境界を決める。なぜそう決めたかは [decisions/](decisions/) にある。

## 最初の実装方針

| 項目 | 方針 |
| --- | --- |
| 言語 | C++17。42 の C++98 課題とは別の独立したリポジトリ([decisions/0001](decisions/0001_language_and_boundaries.md)) |
| ビルド | CMake。実装時に、実際に動かした環境と依存ライブラリの版を README に記録する |
| モデル | Phase 0 で連続 CA と反応拡散を小規模に比較し、Phase 1 に進む候補を選ぶ。採用モデルは未定 |
| 描画 | 当面 SDL3 による 2D 表示を候補とする。ライブラリの型をシミュレーションに持ち込まない |
| 計算 | CPU 上の小さい格子から始める。2 枚の盤面で同期更新する |
| 音 | Phase 0〜1 には実装しない。Phase 2 で合成刺激 → WAV → 必要ならマイク、の順で追加する |

## 責務の境界

```text
InputSource → Stimulus → Simulation → StateView → Renderer
                              ↓
                         Metrics/Snapshot
```

- **Simulation** は状態と設定を所有する。`step(stimulus, fixed_dt)` で 1 ステップ進める。
  - 最初は無音(刺激 0)で動かす。
  - 更新中に書き込み先の盤面を読まない。
  - 連続値の状態は `std::vector<float>` などで持ち、範囲と NaN を検査する。
- **Renderer** はモデルの状態を表示する。表示色の変化と内部状態の変化は別々に評価する。
- **InputSource** は Phase 2 以降で合成刺激や音ファイルから入力を作る。モデルを特定の音声 API と結合しない。
- **Metrics/Snapshot** は数値と再現用の設定を扱う。Phase 0 では最小限にとどめ、保存形式は必要になった時点で定義し、版管理する。

## 時間と再現性

- 更新は固定時間刻みで行う。描画フレーム数から切り離す。
- 周期境界か固定境界か、各モデルで採用したものを記録する。
- seed だけでは再現できない。モデル式、初期条件、浮動小数点演算の順序、入力列も記録する。

## 性能とメモリ

格子サイズを `W × H`、近傍の直径を `K` とすると、直接畳み込みの計算量はおよそ `O(W H K²)` になります。

- まず小さい格子と小さい近傍で動かし、時間を測る。
- FFT、GPU、CUDA は性能上の必要が確認されるまで採用しない。
- `std::vector` が所有するメモリを明確にする。1 ステップごとに大きな配列を確保し直さない。

## 将来の音声経路(今は実装しない)

Phase 2 の設計の目安として書いておきます。実装は Phase 2 に入ってから。

1. 合成刺激で挙動を検証する。
2. WAV を時刻付きで解析する。まず RMS 音量、必要になれば帯域ごとのエネルギー。
3. 入力のクランプと平滑化を明示する。再生位置と特徴量の時刻を対応付ける。
4. 音の信号を描画色に直結するだけでなく、内部更新にも渡す。

参考: [SDL3 ウィンドウ API](https://wiki.libsdl.org/SDL3/SDL_CreateWindowAndRenderer)、[SDL3 WAV API](https://wiki.libsdl.org/SDL3/SDL_LoadWAV)。実装時に公式 API の引数と版を確認する。
