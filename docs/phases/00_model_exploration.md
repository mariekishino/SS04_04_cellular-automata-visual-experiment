# Phase 0 — モデルを観察して選ぶ

**読者:** 実装者(本人とコーディングエージェント)。
**状態:** 実装対象。Phase 0 が終わっても、本人が観察して判断するまで Phase 1 に進まない。
**役割:** Phase 0 の実装範囲と完了条件の正本。共通ルールは [CLAUDE.md](../../CLAUDE.md)、測定方法は [02_experiment_protocol.md](../02_experiment_protocol.md) を参照。

## 目的

42 の Game of Life で学んだ格子・近傍・同期更新を手がかりに、連続値の系でどんな時間変化が得られるかを直接見て理解します。作品の見た目や「生きている感じ」を安定して得られるかは、この段階では探索事項です。

## 実装範囲

1. **2 種類のモデル**を小さい 2D 格子で動かす。
   - **Lenia 型の連続セルオートマトン**
   - **Gray–Scott 型の反応拡散**
   - それぞれの式、状態変数、近傍計算、境界条件、時間刻みを文書化する。
   - 原著や原作者の資料を確認する。単純化した場合は「Lenia 型」などと明記する。
2. **表示と操作。** 同じアプリまたは小さな実験プログラムで、各モデルの状態を時系列で描画する。モデルとプリセットを選び、停止・再開・リセットできるようにする。見える動きの比較を優先し、凝った UI は作らない。
3. **再現に必要な記録。** seed または明示的な初期配置とパラメータを記録する。各モデルで少なくとも 2 つの初期条件を試す。
4. **数値の記録と異常検出。** 最小・最大、総量、前フレームとの差分、占有セル数(閾値を明記)を記録する。NaN/Inf、消滅、全面飽和を検出する。
5. **コードの説明。** 格子の添字、2 枚の盤面、境界処理、近傍計算、`dt` の意味、直接畳み込みの計算量を、コードと対応させて説明する。

## この段階で含めないもの

CPU と小さい盤面だけで進めます。高解像度、FFT、GPU、音声、履歴、可塑性、LLM は含めません。

1D CA は理解を助ける短い学習メモとして試してもよいですが、上記の 2D モデル比較の代わりにはなりません。

## 完了条件

- C++17/CMake でビルドし、実際に 2 モデルの映像を見られる。ビルド方法と動作確認した環境を README に記載する。
- 両モデルについて、初期条件、境界、時間刻み、パラメータ、観測結果を記録する。各モデル少なくとも 2 条件を比較する。
- 同条件の再実行結果を比較できる。著しく異なれば、再現性の原因を調べて報告する。
- 数値異常を検出でき、異常が起きた条件を隠さず記録する。
- Phase 1 の候補を**観察結果と計算負荷に基づいて**提案する。目的に合うモデルがなければ、選定保留という結論でよい。

## 次へ渡す記録

`/phase-report` の様式で短い実験レポートを書く。実行コマンド、モデルごとの数式・出典・設定、画像または動画、指標、失敗例、候補を選ぶ／保留する理由を含める。Phase 1 の数値パラメータは、この観察なしに固定しない。
