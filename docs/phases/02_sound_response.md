# Phase 2 — 音への即時応答

**読者:** 実装者(本人とコーディングエージェント)。
**状態:** 実装済み(2026-09-24、コミット 562da9e / 窓アプリの音声は 6bf6123)。報告は [02_report.md](02_report.md)。実機での音声再生は本人の確認待ち。本人が観察して判断するまで Phase 3 に進まない。
**役割:** Phase 2 の実装範囲と完了条件の正本。共通ルールは [CLAUDE.md](../../CLAUDE.md)、測定方法は [02_experiment_protocol.md](../02_experiment_protocol.md)。

## Phase 1 を受けて確定したこと

- **モデル:** Lenia 型、Orbium パラメータ、周期境界、64×64 を既定にする。開始状態は Orbium 配置に固定する(自発生成は 20 seed 中 2 例だったため)。
- **刺激なしの基準動作:** Orbium の直進を受け入れる([decisions/0004](../decisions/0004_accept_gliding_baseline.md))。刺激の効果は、この基準からの差として測る。
- **刺激の入り口は 2 つとも実装して比較する。** (a) 成長関数への加算 `A' = clip(A + dt·(G(U) + g·s(t)·h(x)))`、(b) mu の変調 `mu_eff = mu + g·s(t)·h(x)`。g は反応の強さ(コードでは `stim_gain`)、s(t) は音から得た 0〜1 の振幅、h(x) は空間の形。
- **空間の形は 2 つ。** 一様 `h = 1` と、片側からの勾配 `h = x / (W−1)`(左 0 → 右 1。周期境界の継ぎ目で不連続になることを記録する)。
- **入力源は 2 つ。** 合成パルス(開始時刻・長さ・周期・振幅を指定)と、WAV の RMS 包絡(窓は 1 シミュレーションステップ分、平滑化の時定数を指定)。MP3 は ffmpeg で WAV に変換してから使う。
- **連結成分数は参考値のまま。** 判定には総量・広がり・速度・進行方向を使う。

## 狙い

音から得た信号が内部更新に作用し、形・速さ・向きの変化として見えるか。音が止んだ後、短期の応答がどう減衰するかを測る。「色が変わる」だけの応答は作らない([00_vision.md](../00_vision.md))。

## 実装範囲

1. **刺激の型と経路。** `Stimulus`(振幅、空間の形)を `Model::step(const Stimulus&)` に渡す。Lenia は入り口(none / growth / mu)と反応の強さをパラメータに持つ。Gray–Scott は刺激を無視する(記録する)。振幅 0 のとき Phase 1 とバイト単位で同一の結果になることをテストする。
2. **入力源。** 合成パルス源と WAV 源。WAV は 16 bit PCM と 32 bit float、モノラル/ステレオ(平均)を読む。1 ステップあたりの実時間(既定 1/60 秒)で RMS を取り、指数移動平均で平滑化し、ファイル内の最大 RMS で正規化して [0,1] にクランプする。正規化の基準値を記録する。
3. **記録。** 各 run に `stimulus.csv`(step, t, 生の振幅, 平滑化後の振幅)を書く。`config.json` に入り口・形・反応の強さ・入力源の設定を含める。
4. **指標の追加。** 進行方向(heading、度)を毎ステップの重心変位から求め、スナップショットごとに記録する。無音 run と音あり run を並べて差を出す比較スクリプトを用意する。
5. **窓アプリ。** `--wav` で WAV を再生しながら、再生と同じ時刻の振幅を刺激として与える(SDL3 の audio を有効化)。VM では音声デバイスがないので dummy ドライバで動作確認し、実機の音は本人が確認する。
6. **コードの説明。** 刺激の経路、WAV の読み方と RMS、平滑化の時定数、再生と刺激の時刻合わせを、コードと対応させて説明する。

## この段階で含めないもの

履歴(長い時定数の内部状態)、可塑性(係数の更新)、複数個体、マイク入力、周波数帯の分解(RMS のみ)、LLM。

## 完了条件

- 振幅 0 の run が Phase 1 と同一である(テスト)。
- 同じ Orbium 開始状態から、無音 / 短い合成パルス / 継続パルス の 3 条件を、入り口 2 × 形 2 の組み合わせで比較した記録がある。各条件で、パルス中の変化(総量・速度・向き・広がり)と、停止後に基準へ戻るまでの時間(減衰)が数値で示されている。
- 反応の強さを変えたときに「効果なし」「見える変化」「消滅」の境界がどこにあるかを記録している。
- 生成した WAV(パルス列、持続音)で同様の比較ができている。
- `stimulus.csv` と `config.json` から入力列を再現できる。
- 数値異常や消滅があれば条件を隠さず記録する。
- Phase 3 で「履歴」として何を足すかの候補を、観察に基づいて提案する。
